# Аутентификация

Система многоуровневой аутентификации Family Budget. Поддерживает три метода: Telegram OAuth (рекомендуемый), Email + Password + 2FA (обязательный TOTP для обычных пользователей), Email + Password без 2FA (только для администраторов — security exception).

## Основные характеристики

### Методы аутентификации

| Метод | 2FA | Применение |
|-------|-----|-----------|
| Telegram OAuth | Нет (встроенный Telegram security) | Основной (рекомендуется) |
| Email + Password + TOTP | **Обязательно** для обычных пользователей | Альтернатива |
| Email + Password | **Нет** (admin bypass) | Экстренный доступ администратора |

### Ключевые механизмы безопасности

- **HMAC-SHA256** — валидация Telegram OAuth данных
- **Argon2id** — хеширование паролей (memory-hard, GPU-resistant)
- **TOTP** — Time-based One-Time Password (30 сек TTL)
- **JWT tokens** — access: 7 дней, refresh: 30 дней в httpOnly cookies
- **Token rotation** — старые refresh tokens отзываются
- **Rate limiting** — 5 попыток логина в минуту на IP
- **Backup codes** — 10 одноразовых кодов для 2FA recovery

### Admin Bypass (security exception)

Администраторы могут войти без 2FA для экстренного доступа. Детектирование на frontend по схеме ответа:
- Обычный пользователь → `{requires_2fa: true, session_token: "..."}`
- Admin bypass → `{access_token: "...", refresh_token: "...", user: {...}}`

Риски митигируются: пароль ≥24 символов (auto-generated), rate limiting, comprehensive logging с `[AUTH_EMAIL]` prefix.

### WebAuthn / Biometrics (v6.5.1+)

После завершения 2FA-setup при первом логине отображается onboarding для биометрии. Использует FastAPI dependency injection (`CurrentUser`), не ручную проверку `request.state`.

### Логирование

Backend префиксы: `[AUTH_EMAIL]`, `[ADMIN_USER]`, `[WEBAUTHN_STATUS]`, `[REGISTER_OPTIONS]`, `[AUTH_VERIFY]`.

## Схема данных

```python
# t_d_user
telegram_id, email, password_hash (Argon2id)
is_admin, is_active
two_factor_enabled, two_factor_secret (TOTP), backup_codes
last_login_at

# t_d_refresh_token
user_id, token_hash (SHA-256), expires_at
```

## Admin Setup

Администраторский аккаунт создаётся через `setup.sh` или `deploy.sh`:
- Автогенерация 24-символьного пароля (случайный, не менее secure чем UUID)
- Email формат: `admin@{domain}`
- Сохраняется в `/opt/budget/.admin_credentials` (ограниченные права)
- Пароль соответствует OWASP 2023: минимум 12 символов, из всех классов

**2FA для admin:** По умолчанию **отключена** (admin bypass), в отличие от обычных пользователей где 2FA обязательна. Это намеренное дизайн-решение для экстренного доступа.

**Риски митигируются:**
- Пароль ≥24 символов (auto-generated)
- Rate limiting 5 попыток/минуту
- Полный audit trail с `[ADMIN_USER]` prefix в логах
