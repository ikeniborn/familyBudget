# Семантическое версионирование

Стратегия единого управления версиями всех компонентов Family Budget на основе формата `X.Y.Z` (Semantic Versioning). Файл `/VERSION` — единственный источник истины.

## Основные характеристики

| Компонент файл | Откуда получает версию |
|----------------|------------------------|
| `/VERSION` | Ручное обновление разработчика |
| `package.json` | Pre-commit hook синхронизирует с VERSION |
| Docker image tags | GitHub Actions читает VERSION |
| HTML `?v=` параметры | CI cache_busting_ci.sh заменяет PLACEHOLDER |
| Service Worker `CACHE_VERSION` | Vite plugin инкрементирует при build |
| `.env` файл | deploy.sh синхронизирует при деплое |

### Правила инкремента

- **Patch (X.Y.Z)**: bug fixes, minor changes (`10.0.23 → 10.0.24`)
- **Minor (X.Y.0)**: новые features, backward compatible (`10.0.23 → 10.1.0`)
- **Major (X.0.0)**: breaking changes (`10.x.x → 11.0.0`)

### Валидация в CI

```yaml
CACHE_VERSION=$(cat VERSION | tr -d '[:space:]')
if [[ ! "$CACHE_VERSION" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]]; then
  echo "❌ Invalid VERSION format"
  exit 1
fi
```

Build завершается с ошибкой, если файл VERSION отсутствует или формат невалиден.

## Применение в контексте Family Budget

VERSION обновляется **вручную** разработчиком перед деплоем — автоматический bump намеренно отключён для строгого контроля версионирования. При конфликте версий в PR — reviewer должен проверить, что версия не конфликтует с другими открытыми PR.
