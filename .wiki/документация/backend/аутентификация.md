# Аутентификация

Система поддерживает три метода входа: Telegram OAuth, Email+Password+2FA для обычных пользователей и Email+Password без 2FA для администраторов. Используется JWT в httpOnly cookie.

## Основные характеристики

| Метод | 2FA | Применение |
|-------|-----|-----------|
| Telegram OAuth | Нет (безопасность Telegram) | Основной, рекомендуемый |
| Email + Password + TOTP | Обязательно | Альтернатива без Telegram |
| Email + Password (Admin) | Нет (исключение) | Аварийный доступ |

**Ключевые параметры безопасности:**
- HMAC-SHA256 — валидация Telegram OAuth
- Argon2id — хеширование паролей (memory-hard, OWASP 2023)
- TOTP — Time-based One-Time Password для 2FA (30-секундные коды)
- JWT access tokens: 7 дней, refresh tokens: 30 дней (httpOnly cookie)
- Token rotation: старые refresh tokens отзываются при обновлении
- Rate limiting: 5 попыток входа в минуту на IP

## Telegram OAuth

**Поток:**
1. Пользователь нажимает «Войти через Telegram»
2. Telegram Widget валидирует через HMAC-SHA256
3. Backend создаёт/обновляет пользователя в БД
4. Генерация JWT, установка httpOnly cookie
5. Редирект на dashboard

**Код:**
```python
@router.post("/telegram")
async def telegram_login(data: TelegramAuthData, ...):
    if not validate_telegram_auth(data, settings.TELEGRAM_BOT_TOKEN):
        raise HTTPException(401, "Invalid Telegram data")
    user = await get_user_by_telegram_id(session, data.id)
    # create or update user, generate JWT
```

## Email + Password + 2FA (обычные пользователи)

**Поток:**
1. Email + пароль → backend создаёт 2FA-сессию (TTL 5 минут)
2. Если первый вход: `/2fa-setup-login` (QR-код)
3. Если 2FA настроена: `/2fa-verify` (ввод TOTP-кода)
4. Валидация кода → JWT tokens

**v6.5.1+:** После настройки 2FA предлагается включить биометрию (WebAuthn onboarding).

## Admin bypass (Email без 2FA)

**Назначение:** Аварийный доступ (потеря 2FA-устройства, восстановление системы).

**Определение:** Frontend получает `AuthResponse` (с `access_token`) вместо `EmailLoginResponse` (с `requires_2fa`):
```javascript
if (data.access_token && data.refresh_token) {
    // Admin bypass — редирект сразу на dashboard
    window.location.href = '/';
}
```

**Меры безопасности:**
- Минимум 24 символа (auto-generated setup.sh)
- Argon2id хеширование
- Rate limiting 5/мин
- Полное логирование с префиксом `[AUTH_EMAIL]`

## WebAuthn (биометрия)

Все WebAuthn-эндпоинты используют dependency injection:
```python
@router.post("/webauthn/register/options")
async def register_options(current_user: CurrentUser, ...):
    # CurrentUser загружается автоматически через FastAPI DI
```

**Ошибка:** Использовать `request.state.user` (НЕВЕРНО — middleware устанавливает только `request.state.user_id`).

## Модели БД

**User (`t_d_user`):**
```python
telegram_id: int | None        # Telegram OAuth
email: str | None              # Email login
password_hash: str | None      # Argon2id
is_admin: bool                 # Admin bypass флаг
two_factor_enabled: bool       # TOTP статус
two_factor_secret: str | None  # TOTP секрет
backup_codes: str | None       # 10 одноразовых кодов
```

**RefreshToken (`t_d_refresh_token`):**
```python
user_id: int       # FK → t_d_user
token_hash: str    # SHA-256 хеш (не plain text!)
expires_at: datetime
```

## Конфигурация (переменные окружения)

```bash
TELEGRAM_BOT_TOKEN=...
ADMIN_TELEGRAM_ID=...
ADMIN_EMAIL=...         # Опционально — аварийный доступ
ADMIN_PASSWORD=...      # Auto-generated (24 символа)
JWT_SECRET=...          # openssl rand -hex 32
JWT_EXPIRE_DAYS=7
TELEGRAM_PROXY_URL=...  # HTTP/HTTPS/SOCKS5 для серверов без прямого доступа к api.telegram.org
```

## Логирование

| Префикс | Контекст |
|---------|---------|
| `[AUTH_EMAIL]` | Email/password события |
| `[ADMIN_USER]` | Создание admin-пользователя |
| `[WEBAUTHN][*]` | WebAuthn операции (REGISTER_OPTIONS, VERIFY, и т.д.) |

PII защита: email-адреса логируются только как SHA-256-хеши (первые 8 символов).
