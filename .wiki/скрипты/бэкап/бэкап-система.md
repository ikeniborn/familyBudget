# Система резервного копирования

Автоматизированная система бэкапов PostgreSQL: локальное хранение + выгрузка в Yandex Object Storage (S3-совместимый). Включает скрипты создания (`backup.sh`), восстановления (`restore.sh`), мониторинга (`check_backup_health.sh`) и Python-утилиту для S3 (`s3_backup.py`).

## Основные характеристики

### Параметры хранения

| Хранилище | Ретенция | Формат |
|-----------|----------|--------|
| Локальное | 7 дней | `backup_YYYYMMDD_HHMMSS.sql.gz` |
| S3 | 28 дней | `postgresql-backups/YYYY/MM/backup_*.sql.gz` |

### backup.sh — создание бэкапа

**Опции:**
- `--force-s3` — принудительная выгрузка в S3 (независимо от дня)
- `--verbose` — детальный вывод

**Переменные окружения (из .env):**
```
POSTGRES_USER, POSTGRES_DB, POSTGRES_PASSWORD
S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY
S3_BUCKET_NAME
S3_ENDPOINT_URL  (по умолч.: https://storage.yandexcloud.net)
```

**Коды завершения:**
- `0` — успех
- `1` — ошибка бэкапа
- `2` — ошибка конфигурации
- `3` — lock-файл существует (другой процесс)
- `4` — ошибка S3-выгрузки (локальный бэкап сохранён)

**Lock-файл:** `/tmp/familybudget_backup.lock` — защита от параллельного запуска.

### restore.sh — восстановление

Интерактивный скрипт с явным подтверждением (approval gate) перед восстановлением:

- Интерактивный выбор бэкапа из списка (с метаданными)
- Загрузка бэкапа из S3 при необходимости
- Создание safety-бэкапа перед восстановлением
- Опция `--yes` — пропуск подтверждений (осторожно!)
- `--backup-file <path>` — прямое указание файла

### s3_backup.py — Python S3-утилита

Заменяет зависимость от AWS CLI на чистый Python (boto3):

```bash
# Загрузка файла
./s3_backup.py upload <file> <s3_key> --bucket <name> --endpoint-url <url>

# Очистка по ретенции
./s3_backup.py cleanup --retention-days <days> --bucket <name> --endpoint-url <url>
```

### check_backup_health.sh — мониторинг

Проверяет состояние бэкапов; интегрируется в Nagios, Prometheus (textfile collector), cron:

**Пороги:**
- `MAX_BACKUP_AGE_HOURS=26` — тревога если бэкап старше 26 ч
- `MIN_BACKUP_SIZE_KB=100` — тревога если файл меньше 100 КБ
- `WARN_DISK_USAGE_PERCENT=80` — предупреждение при заполненности диска >80%

**Коды завершения:**
- `0` — всё в норме
- `1` — предупреждение
- `2` — критическая ошибка
- `3` — ошибка конфигурации

**Форматы вывода:** текст или JSON (`--json`).
