## 1. Архитектура системы уведомлений

### 1.1 Notification Service (Основной сервис)

**Файл:** `bot/utils/notification_service.py`

**Назначение:** Проверка превышения бюджета и отправка автоматических уведомлений.

#### Метод: `check_budget_threshold()`

**Параметры:**
- `token` - JWT токен пользователя для API
- `telegram_id` - Telegram ID получателя
- `article_id` - ID категории бюджета для проверки
- `threshold_percent` - Порог срабатывания (по умолчанию 90%)

**Логика работы:**
1. Получает факты за текущий месяц из API
2. Разделяет на "plan" (план) и "fact" (факт)
3. Считает итоги по категориям
4. Проверяет: факт >= порог% от плана
5. Проверяет дубликаты через `_notification_already_sent()`
6. Создает запись уведомления в БД

**Условия отправки:**
- 🚨 **"ПРЕВЫШЕН"** - если процент >= 100%
- ⚠️ **"ДОСТИГНУТ ПОРОГ"** - если процент >= порога (90%)

#### Пример сообщения о превышении бюджета:

```markdown
⚠️ *Бюджетное предупреждение*
---
ЦФО: Семья
Категория: Продукты
Статус: ДОСТИГНУТ ПОРОГ
---
*Статистика:*
План: 50 000.00 ₽
Факт: 45 000.00 ₽
Использовано: 90%
```

**Метод отправки:**
```python
await self.bot.send_message(
    chat_id=telegram_id,
    text=message,
    parse_mode="Markdown"
)
```

**Обработка ошибок:** Перехватывает `TelegramError` и логирует неудачи.

## 2. Автоматические уведомления

### 2.1 Уведомления о превышении бюджета

**Триггер:** Spending >= пороговый процент от плана
**Частота:** Один раз за месяц на категорию
**Получатель:** Один пользователь

**Варианты сообщений:**

#### Вариант 1: Достигнут порог (90%)
```
⚠️ *Бюджетное предупреждение*
---
ЦФО: Семья
Категория: Продукты
Статус: ДОСТИГНУТ ПОРОГ
---
*Статистика:*
План: 50 000.00 ₽
Факт: 45 000.00 ₽
Использовано: 90%
```

#### Вариант 2: Превышен бюджет (100%+)
```
🚨 *Бюджетное предупреждение*
---
ЦФО: Семья
Категория: Развлечения
Статус: ПРЕВЫШЕН
---
*Статистика:*
План: 5 000.00 ₽
Факт: 5 500.00 ₽
Использовано: 110%
```

### 2.2 Еженедельные отчеты

**Статус:** ⚠️ Временно отключен
**Планируемая частота:** Каждое воскресенье 20:00
**Получатели:** Все пользователи с включенными уведомлениями

**Формат:** См. раздел 1.2 выше

## 4. PWA Push-уведомления

**Файл:** `backend/app/api/v1/endpoints/push.py`

### 4.1 Управление VAPID ключами

**Endpoint:** `GET /api/v1/push/vapid-key`

**Ответ:** VAPID публичный ключ для подписки браузера

**Проверка статуса:** Валидация что VAPID ключи настроены (не placeholder)

### 4.2 Подписка на push-уведомления

**Подписаться:** `POST /api/v1/push/subscribe`
- Сохраняет подписку браузера в БД
- Требует настроенный VAPID

**Отписаться:** `POST /api/v1/push/unsubscribe`
- Удаляет подписку по endpoint

**Отправить тест:** `POST /api/v1/push/notify` (только admin)
- Тестовый endpoint для отправки push
- **Статус:** Реализация закомментирована (skeleton code)
- Планируется использование библиотеки `pywebpush`

### 4.3 Формат push-сообщения (планируемый)

```json
{
  "title": "Уведомление о бюджете",

  "icon": "/static/icons/icon-192.png",
  "badge": "/static/icons/icon-192.png",
  "tag": "budget-notification",
  "data": {}
}
```

## 6. Статистика и метрики

### 6.1 По типам сообщений

- **Приветствие/Welcome:** 7 вариаций
- **Сообщения об ошибках:** 25+ вариантов (авторизация, валидация, API ошибки)
- **Отображение данных:** 15+ (статистика, списки, отчеты)
- **Сообщения загрузки:** 10+ (с контекстным текстом)
- **Подтверждения:** 5+ (перед удалением, редактированием и т.д.)

### 6.2 Языки

- **Основной:** Русский - Все сообщения
- **Поддерживается (не реализовано):** Английский доступен в настройках (не полностью реализовано в ответах бота)

### 6.3 Элементы форматирования

**Эмодзи:** Активное использование
- 💰💵💸 - Деньги, финансы
- 📊📝📅 - Данные, документы, даты
- 🔍🚀 - Поиск, действия
- ⏳✅❌ - Статусы
- ⚠️🚨🔔 - Уведомления, алерты

**Текстовые стили:**
- **Жирный:** Названия категорий, суммы, выделенный текст
- _Курсив:_ Подсказки, вторичная информация, детали ошибок
- **Блоки кода:** Не используются в текущей реализации
- **Markdown ссылки:** Не используются в текущей реализации

### 6.4 Типы клавиатур

1. **WebApp Button:** Команда `/start` (открывает webapp)
