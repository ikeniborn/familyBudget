## [Версия 3.5.2] - 2025-09-17

### 🔧 Исправление аутентификации страницы статей

#### Устранение 401 ошибок на странице управления статьями
- **Проблема**: Пользователи получали 401 Unauthorized при доступе к `/settings/articles`
- **Корневая причина**: Избыточные клиентские проверки аутентификации в компоненте

  - 401 ошибка при загрузке страницы статей

  - Функциональность статей полностью заблокирована

#### Техническое решение
- **Удаление AuthGuard**: Убраны избыточные клиентские проверки аутентификации из компонента
- **Упрощение архитектуры**: Использование стандартной серверной аутентификации через `+layout.server.ts`
- **Исправленные файлы**:
  - `frontend-svelte/src/routes/(protected)/settings/articles/+page.svelte` - удален AuthGuard
- **Результат**: Страница статей теперь доступна для аутентифицированных пользователей

#### Результат исправления
- ✅ Полное устранение 401 ошибок на странице статей
- ✅ Восстановлена функциональность управления статьями
- ✅ Упрощена архитектура аутентификации компонента
- ✅ Соответствие стандартной схеме защиты маршрутов приложения

#### Техническая документация
- **Принцип решения**: Устранение дублирования проверок аутентификации
- **Архитектура**: Использование единой серверной проверки доступа

### 🔧 Исправление ошибки маппинга полей в компоненте ReportFilters

#### Проблема
- **Описание**: Страница отчетов /reports выбрасывала TypeError "Cannot read properties of undefined (reading 'toString')"
- **URL**: http://localhost:5173/reports
- **Симптомы**:
  - Страница не загружалась, показывала критическую ошибку
  - Ошибка в компоненте ReportFilters.svelte на строках 83-86 и 91-94
  - Попытка обращения к несуществующим полям объектов

#### Корневая причина
- **Несоответствие полей при маппинге данных** из store в компоненте ReportFilters
- Компонент использовал устаревшие поля:
  - `financial_center_id` и `financial_center_name` вместо стандартизированных `id` и `name`
  - `cost_center_id` и `cost_center_name` вместо стандартизированных `id` и `name`
- API возвращает объекты с новыми полями, но компонент ожидал старые

#### Решение
- **Файл**: `frontend-svelte/src/lib/components/reports/ReportFilters.svelte`
- **Изменения**:
  - Строки 83-86: Добавлена обратная совместимость для FinancialCenter
    - `fc.financial_center_id.toString()` → `(fc.id || fc.financial_center_id || 0).toString()`
    - `fc.financial_center_name` → `fc.name || fc.financial_center_name || 'Без названия'`
  - Строки 91-94: Добавлена обратная совместимость для CostCenter
    - `cc.cost_center_id.toString()` → `(cc.id || cc.cost_center_id || 0).toString()`
    - `cc.cost_center_name` → `cc.name || cc.cost_center_name || 'Без названия'`

#### Результат
- ✅ Страница отчетов загружается без ошибок
- ✅ Фильтры работают с обеими версиями структуры данных
- ✅ Добавлены fallback значения для отсутствующих полей
- ✅ Компонент устойчив к изменениям API

#### Тестирование
- **Добавлен тест**: `frontend-svelte/src/lib/components/reports/ReportFilters.test.ts`
- Покрытие сценариев:
  - Работа с новой структурой полей (id, name)
  - Обратная совместимость со старой структурой

## [Версия 3.1.5] - 2025-09-14

### 🔧 Критическое исправление удаления периодов с зависимостями

#### Исправление SQLAlchemy Detached Session Error
- **Проблема**: При удалении периодов с записями в реестре возникала 500 ошибка вместо корректного 409 Conflict
- **Корневая причина**: Доступ к `period.ru_name` после database rollback приводил к detached session ошибке
- **Симптомы**:
  - `sqlalchemy.exc.DetachedInstanceError` при попытке удалить период с зависимостями
  - Пользователи получали 500 Internal Server Error вместо понятного сообщения
  - Отсутствие информации о причинах невозможности удаления
- **Решение**:
  - Сохранение `period_name = period.ru_name` ДО попытки удаления
  - Обработка `IntegrityError` с возвратом корректного 409 Conflict
  - Информативные сообщения об ошибках с указанием имени периода
  - Детализация причины конфликта (связанные записи в реестре операций)
- **Файлы изменены**:
  - `backend-fastapi/app/api/v1/endpoints/periods.py` - исправлена логика удаления периодов
  - `backend-fastapi/app/crud/crud_period.py` - улучшенная обработка foreign key violations

### 🔧 Техническая реализация

#### Модуль app.core.response
```python
def success_response(data: Any, total: Optional[int] = None) -> Dict[str, Any]:
    """Создать успешный ответ API"""
    response = {"success": True, "data": data}
    if total is not None:
        response["total"] = total
    return response

def error_response(message: str, status_code: int = 400) -> JSONResponse:
    """Создать ответ с ошибкой API"""
    return JSONResponse(
        status_code=status_code,
        content={"success": False, "error": message}
    )
```

#### TypeScript интерфейсы (Frontend)
```typescript
interface ApiResponse<T> {
```
