## Структура анализа FAB системы

### fab-speed-dial-analysis.md

**Разделы:**
1. Обзор системы FAB (Mobile/Desktop режимы)
2. Сравнительная таблица реализаций (19 критериев × 3 компонента)
3. Детальный анализ компонентов:
   - `fab_toolbar.html` - универсальный компонент
   - `fab_buttons.html` - списки покупок
   - Admin страницы
4. Стили и визуальное оформление (Material Design)
5. Z-Index иерархия (13 слоев)
6. Рекомендации по улучшению (7 областей)

**Ключевые находки:**
- ✅ Адаптивная система с 2 breakpoints (1024px, 1280px)
- ✅ Material Design elevation и размеры (48px/56px/64px)
- ✅ Централизованный z-index через CSS variables
- ⚠️ Разное поведение FAB на разных страницах (требует унификации)
- ⚠️ Desktop FAB не адаптируется к offline режиму

### fab-visual-schema.md

**Разделы:**
1. Адаптивное поведение по страницам (ASCII схемы)
2. Позиционирование FAB (координаты и отступы)
3. Z-Index визуализация (вертикальная иерархия)
4. Анимационные переходы (timeline диаграммы)

**Визуализации:**
- 📐 Layout схемы для каждой страницы (Desktop/Mobile)
- 📍 Точные координаты позиционирования
- 📊 Z-Index иерархия (13 слоев)
- ⏱️ Timeline анимаций (Speed Dial, Hover, Backdrop)

## Как использовать эту директорию

### Для разработчиков

1. **Перед добавлением новых FAB:**
   - Изучить `fab-speed-dial-analysis.md` → раздел "Сравнительная таблица"
   - Проверить z-index через `fab-visual-schema.md` → раздел "Z-Index визуализация"
   - Следовать Material Design размерам (48/56/64px)

2. **Перед изменением существующих FAB:**
   - Проверить влияние на другие страницы через сравнительную таблицу
   - Учесть рекомендации из раздела "Рекомендации по улучшению"

3. **При багах с позиционированием:**
   - Консультироваться с разделом "Позиционирование FAB" → точные координаты

### Для менеджеров продукта

1. **Планирование унификации UX:**
   - Использовать раздел "Рекомендации по улучшению" как roadmap
   - Приоритизировать фикс разного поведения FAB (рекомендация #1)

2. **Оценка impact изменений:**
   - Сравнительная таблица показывает все зависимости компонентов

### Для QA

1. **Тестирование адаптивности:**
   - Использовать визуальные схемы как expected behavior
   - Проверять все breakpoints (640px, 1024px, 1280px)

2. **Проверка анимаций:**
   - Timeline диаграммы показывают ожидаемые задержки и эффекты
