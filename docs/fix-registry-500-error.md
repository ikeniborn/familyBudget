# Исправление ошибки 500 при добавлении фактических операций

## Дата: 2025-09-03

### Описание проблемы
При попытке добавить фактические операции через форму в интерфейсе возникала ошибка HTTP 500. Из логов backend сервиса видно:

```
sqlalchemy.exc.IntegrityError: (sqlalchemy.dialects.postgresql.asyncpg.IntegrityError) <class 'asyncpg.exceptions.ForeignKeyViolationError'>: insert or update on table "t_f_registry" violates foreign key constraint "fk_t_f_registry_row_type_id_t_d_row_type"
DETAIL: Key (row_type_id)=(2) is not present in table "t_d_row_type".
```

### Корневая причина
Таблица `t_d_row_type` была пустая, отсутствовали базовые записи:
- `1` - Plan (Планируемые операции)  
- `2` - Fact (Фактические операции)

При попытке создать фактическую операцию система пыталась установить `row_type_id=2`, но такой записи не существовало в справочной таблице.

### Примененное решение

1. **Добавлены недостающие записи в БД:**
   ```sql
   INSERT INTO t_d_row_type (row_type_id, row_type_name) 
   VALUES (1, 'Plan'), (2, 'Fact') 
   ON CONFLICT (row_type_id) DO NOTHING;
   ```

2. **Создана SQL миграция** `init_row_type_data.sql` для автоматической инициализации справочника при развертывании системы.

3. **Проверена корректность моделей данных:**
   - Модель `RowType` корректно настроена
   - Внешний ключ в модели `Registry` правильно ссылается на `t_d_row_type`
   - Форма `FactForm.svelte` правильно устанавливает `row_type_id: 2` для фактических операций

### Файлы изменений
- `/backend-fastapi/migrations/init_row_type_data.sql` - новая миграция
- Данные в таблице `t_d_row_type` - добавлены базовые записи

### Тестирование
- ✅ Сервисы запускаются без ошибок
- ✅ В логах backend нет ошибок 500
- ✅ Таблица `t_d_row_type` содержит необходимые записи
- ✅ Форма добавления операций настроена корректно

### Предотвращение повторных проблем
1. Миграция `init_row_type_data.sql` будет автоматически применяться при инициализации новых экземпляров БД
2. Использование `ON CONFLICT DO NOTHING` предотвращает дублирование записей
3. Sequence правильно настроен для последующих вставок
