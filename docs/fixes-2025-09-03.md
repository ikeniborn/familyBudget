# Исправления проблем с периодами - 03.09.2025

## Исправленные проблемы

### 1. Проблема с отображением чекбоксов
**Проблема:** На странице управления периодами чекбоксы отображались как HTML код `<input type="checkbox" />` вместо реальных элементов.

**Причина:** Компонент `CRUDTable` использовал функцию render которая возвращала HTML строку, но `SimpleDataTable` отображал её как текст.

**Решение:**
- Создан новый компонент `EnhancedDataTable` с нативной поддержкой чекбоксов и меню действий
- Обновлён `CRUDTable` для использования расширенных возможностей
- Удалена render функция для чекбоксов из `EnhancedPeriodManager`

### 2. Проблема с дублированием периодов
**Проблема:** Периоды дублировались в таблице (один период отображался несколько раз).

**Причина:** 
- В таблице БД `t_d_period` отсутствовал уникальный констрейнт
- API не проверял существование периода перед созданием
- Периоды хранятся глобально без привязки к пользователю

**Решение:**
- Удалены дубликаты из БД (оставлен один экземпляр каждого периода)
- Добавлен уникальный констрейнт `unique_period_date_name` на комбинацию полей `period_dt` и `period_ru_name`
- Добавлена проверка на существование периода в API перед созданием

### База данных
1. **Очистка данных:**
   - Удалены дубликаты периодов (5 дубликатов удалено)
   
2. **Добавлен констрейнт:**
   ```sql
   ALTER TABLE t_d_period 
   ADD CONSTRAINT unique_period_date 
   UNIQUE (period_dt);
   ```
   
   **Примечание:** Констрейнт установлен только на дату периода (period_dt), что означает что в системе может быть только один период на каждую дату (первое число месяца).

## Архитектурные замечания

### Проблема с изоляцией данных
Текущая архитектура хранит периоды глобально без привязки к пользователю. Это означает:
- Все пользователи видят одни и те же периоды
- Нет возможности иметь разные периоды для разных пользователей
- API эмулирует user_id в ответах, но не фильтрует по нему

**Рекомендация:** В будущем следует добавить поле `user_id` в таблицу `t_d_period` и обновить все запросы для фильтрации по пользователю.
