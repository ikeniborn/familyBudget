<delegation_strategy>
ОБЯЗАТЕЛЬНОЕ ИСПОЛЬЗОВАНИЕ СПЕЦИАЛИЗИРОВАННЫХ АГЕНТОВ:

Для эффективного решения задач используй следующих агентов по их специализации:

- `api-developer` → Изменения REST API endpoints, OpenAPI схемы
- `frontend-developer` → Svelte компоненты, страницы, UI логика
- `database-designer` → Схема БД, индексы, миграции, оптимизация запросов
- `typescript-developer` → Типы TypeScript, интерфейсы, generic компоненты
- `backend-developer` → Бизнес-логика, сервисы, валидация данных
- `docker-deployment-expert` → Docker конфигурация, контейнеры, сети
- `test-engineer` → Написание и обновление тестов, проверка покрытия
- `code-documenter` → Документация кода, API, архитектурные решения
- `code-security-auditor` → Проверка безопасности, изоляция данных

ПРАВИЛА ДЕЛЕГИРОВАНИЯ:
1. Анализируй задачу и определяй необходимых агентов
2. Делегируй параллельно независимые задачи разным агентам
3. Используй агентов для их прямой специализации
4. Для сложных задач комбинируй несколько агентов
</delegation_strategy>

<technical_constraints>
ОБЯЗАТЕЛЬНЫЕ ОГРАНИЧЕНИЯ:
- Все операции через Docker контейнеры (budget-frontend, budget-backend, budget-postgres)
- НЕ запускать npm/pip/node напрямую на хосте
- УПРАВЛЕНИЕ КОНТЕЙНЕРАМИ:
  * Проверять статус контейнеров перед запуском: `docker ps -a | grep budget-`
  * Если контейнер уже запущен - ПЕРЕЗАПУСКАТЬ, а НЕ создавать новый процесс
  * Использовать `docker restart budget-frontend` вместо повторного `docker exec npm run dev`
  * НЕ допускать дублирующих процессов в контейнерах
  * Убивать зависшие процессы перед перезапуском: `docker exec budget-frontend pkill -f "npm run dev"`
- Соблюдать изоляцию данных по user_id во всех запросах
- Следовать существующим паттернам кода
- Файлы не более 500 строк
- Минимум 80% покрытие тестами для новой функциональности
</technical_constraints>

## Фаза 4: РЕАЛИЗАЦИЯ И ИНТЕГРАЦИЯ
<thinking>
- Все ли изменения согласованы между компонентами?
- Соблюдены ли паттерны проекта?
- Нет ли конфликтов в изменениях?
- Нет ли дублирующих процессов в контейнерах?
</thinking>

Действия:
1. Применить изменения используя `MultiEdit` для batch операций
2. Проверить статус контейнеров и процессов:
   ```bash
   # Проверить запущенные контейнеры
   docker ps | grep budget-
   
   # Проверить процессы в контейнерах
   docker exec budget-frontend ps aux | grep "npm run dev"
   docker exec budget-backend ps aux | grep uvicorn
   ```
3. Управление контейнерами (ВАЖНО!):
   ```bash
   # Если есть дублирующие процессы - убить их
   docker exec budget-frontend pkill -f "npm run dev" || true
   docker exec budget-backend pkill -f uvicorn || true
   
   # Перезапустить контейнеры (НЕ создавать новые процессы!)
   docker restart budget-frontend
   docker restart budget-backend
   
   # ИЛИ для полного перезапуска всех сервисов
   docker-compose restart
   ```
4. Проверить тесты и типизацию:
   ```bash
   docker exec budget-backend python -m pytest
   docker exec budget-frontend npm run check
   ```
5. Обновить типы и интерфейсы если изменилась структура данных
6. Добавить/обновить документацию через `code-documenter`

Критерий завершения: Код компилируется и проходит линтинг
Checkpoint: Все изменения применены и не ломают существующий код
