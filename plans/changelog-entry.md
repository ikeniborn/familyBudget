### [Bug Fixes] Автоматическая активация админа при первом создании

**Изменения:**
- 🐛 Исправлено: Первый администратор теперь автоматически активируется при первом входе
- ✨ Добавлена проверка `telegram_id == ADMIN_TELEGRAM_ID` при создании пользователя
- 📝 Обновлена документация: `.env.example` и PRD секция 9.1

**Влияние на пользователей:**
При первоначальной установке системы администратор (определяемый через `ADMIN_TELEGRAM_ID` в `.env`)
автоматически получает доступ к системе без необходимости ручной активации через БД.
Это исправляет проблему "замкнутого круга", когда активировать пользователей может только
активный админ, но сам админ создается неактивным.

**Технические детали:**
- Файлы: `backend/app/api/v1/endpoints/auth.py`, `backend/.env.example`, `docs/prd/09-security-authentication.md`
- PRD: FR-030 (Authorization), 09-security-authentication.md (User Activation Flow)
- Commits:
  - fix: автоматическая активация админа при первом создании
  - docs: обновить документацию для ADMIN_TELEGRAM_ID

**Breaking Changes:** Нет

**Требования к конфигурации:**
- Обязательно установить `ADMIN_TELEGRAM_ID` в `.env` перед первым запуском
- Получить Telegram ID можно через @userinfobot в Telegram
- Значение должно соответствовать Telegram ID первого администратора
