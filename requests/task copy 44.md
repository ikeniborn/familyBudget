
# Task Execution

## Конфигурация
- Режим: последовательное выполнение
- Thinking: enabled, mode=interleaved (использовать для критичных шагов)
- Валидация: targeted, critical_only (блокирующая для acceptance/PRD)
- Среда: локальная разработка (без /opt/, без запущенных сервисов)
- Git: обязателен (branch → commit → push)

## Принципы
1. PRD Compliance - все решения ДОЛЖНЫ соответствовать PRD из `docs/prd`
2. Acceptance Criteria - все критерии ДОЛЖНЫ быть выполнены
3. План ДОЛЖЕН быть согласован перед выполнением

---

## Задачи

1. Изучить варианты интеграции с апи тинькофф для получения данных по транзакциям
2. Использовать Open Banking API (стандарт PSD2). Реалзиовтаь синхронизацию в реалтайм с записью исходх данных в БД
3. Продумать процесс доббавления новых записей в транзакции. НУжно обогозать данными цфо и категориями.
4. Нужно показывать отдельный списко транзакций который надо добавить и обогатить. Не все должны попадать в трназакции. Которые не нужно отмечать как не активные.
5. Хранить секреты от апи в БД в зашифрованном виде с солт.

---

## Процесс

### 1. АНАЛИЗ
1. **[THINKING]** Загрузить и изучить PRD из `docs/prd` - проверить alignment задачи
2. **[THINKING]** Проанализировать текущее состояние, определить root causes
3. **ЗАДАТЬ УТОЧНЯЮЩИЕ ВОПРОСЫ** (если нужно)
4. **[THINKING]** Обдумать решение пошагово
5. Создать TODO план в формате:
```
ПЛАН
════════════════════════════════════════════
PRD: ✓ [релевантные секции]
ПРОБЛЕМЫ: [проблема] → [решение]
ФАЙЛЫ: [файл] - [что изменить]
ШАГИ: 
  1. Git: создать ветку [имя] из [база]
  2. [шаг]
  ...
  N. Git: commit и push
РИСКИ: [список]
ВАЛИДАЦИЯ: [как проверить]
════════════════════════════════════════════
```
**Exit:** PRD проверен, план детализирован, риски идентифицированы

### 2. СОГЛАСОВАНИЕ
**СТОП: Показать план и дождаться подтверждения**

### 3. ВЫПОЛНЕНИЕ
Действовать строго по плану:
- После каждого шага: проверка синтаксиса
- Документировать решения inline
- НЕ запускать сервисы/интеграционные тесты

**Exit:** Все шаги выполнены, код работает, нет syntax errors

### 4. ВАЛИДАЦИЯ (БЛОКИРУЮЩАЯ)
**Критичные проверки (нельзя продолжать без ✓):**
1. **[BLOCKING]** Acceptance criteria - каждый критерий ✓
2. **[BLOCKING]** PRD compliance - нет противоречий
3. Синтаксис всех файлов

**Approval Gate (обязателен):**
```
ВАЛИДАЦИЯ ЗАВЕРШЕНА
- Acceptance Criteria: ✓/✗
- PRD Compliance: ✓/✗
- Syntax Check: ✓/✗
```
**Exit:** Acceptance выполнены, PRD соблюден, тесты написаны

### 5. ФИНАЛИЗАЦИЯ
1. Обновить документацию PRD
2. Git commit с описательным сообщением
3. Git push
4. Вывести summary в формате:
```
SUMMARY
════════════════════════════════════════════
СТАТУС: ✓ COMPLETED
СДЕЛАНО: [список]
ФАЙЛЫ: [файл] - [изменения]
ACCEPTANCE: ✓ [каждый критерий]
PRD: ✓
РЕШЕНИЯ: [решение] - [обоснование]
GIT: branch [имя], commit [hash], pushed
NEXT STEPS: [если есть]
════════════════════════════════════════════
```

## Error Handling

**PRD_CONFLICT** → STOP, уточнить у пользователя  
**ACCEPTANCE_FAIL** → исправить, max 2 попытки  
**SYNTAX_ERROR** → исправить немедленно

**КРИТИЧНО - выполнить в этом порядке:**
1. Прочитать задачи из промпта
2. **ПЕРВЫМ ДЕЛОМ** загрузить PRD из `docs/prd`
3. Использовать thinking для анализа и планирования
4. План ДОЛЖЕН быть согласован перед выполнением
5. При конфликте с PRD - немедленная ОСТАНОВКА
