# SQL Scripts Execution Order

Generated SQL scripts for Family Budget database initialization.

## Execution Order

Execute scripts in the following order:

```bash
# 1. Dimension tables (shared across all users)
psql -U budget_user -d family_budget -f 01_insert_t_d_financial_center.sql
psql -U budget_user -d family_budget -f 02_insert_t_d_cost_center.sql

# 2. Article dimension (parent categories)
psql -U budget_user -d family_budget -f 03_insert_t_d_article_parents.sql

# 3. Article dimension (child categories)
# NOTE: Triggers will automatically populate t_d_article_hierarchy!
psql -U budget_user -d family_budget -f 04_insert_t_d_article_children.sql

# 4. Insert budget facts (plan and actual transactions)
# NOTE: Partitions are created via Alembic baseline migration (backend/db/migrations/)
# 96 monthly partitions (2023-01 to 2030-12) are created automatically
psql -U budget_user -d family_budget -f 06_insert_t_f_budget_fact.sql
```

## Important Notes

### ⚠️ t_d_article_hierarchy - Auto-created by triggers!

**DO NOT** manually insert into `t_d_article_hierarchy` table!

The hierarchy is **automatically maintained** by database triggers:
- Trigger: `trg_article_hierarchy_insert_after` (007_create_article_hierarchy_triggers.sql)
- When you INSERT into `t_d_article`:
  1. Self-reference created (depth=0)
  2. If `parent_id` is set - all ancestor paths copied automatically

**No script 05_insert_t_d_article_hierarchy.sql needed!**

### Partitions (via Alembic)

**⚠️ ВАЖНО:** Файл `05_create_partitions_t_f_budget_fact.sql` был **УДАЛЕН**.

Партиции для `t_f_budget_fact` теперь создаются через Alembic baseline migration:
- **Location**: `backend/db/migrations/versions/20251109_001_baseline_schema_v5_0_0.py`
- **Type**: MONTHLY partitions (better performance than yearly)
- **Count**: 96 partitions (2023-01 to 2030-12)
- **Benefit**: Eliminates overlap conflict between yearly and monthly partitions

### Statistics

- **Financial Centers**: 4 (Илья, Оксана, Радомир, Семья)
- **Cost Centers**: 30
- **Articles (Parents)**: 32 root categories
- **Articles (Children)**: 60 subcategories
- **Partitions**: 96 monthly partitions (via Alembic, not SQL script)
- **Budget Facts**: 6,662 transactions (plan + fact)

### Data Range

- **CSV Data**: 2023-01-01 to 2025-11-01
- **Partitions**: 2023-01-01 to 2030-12-31 (fixed for future data)

### Batch Processing

File `06_insert_t_f_budget_fact.sql` uses batched INSERT:
- **Batch size**: 1000 records per transaction
- **Total batches**: 7 (6 full + 1 partial)
- **Performance**: Optimized for large data imports

## Verification

After execution, verify the data:

```sql
-- Check dimensions

SELECT COUNT(*) FROM t_d_article_hierarchy WHERE depth = 1;  -- Expected: 60 (parent-child)

-- Check partitions
SELECT tablename FROM pg_tables
WHERE tablename LIKE 't_f_budget_fact_%'
ORDER BY tablename;  -- Expected: 96 partitions

-- Check facts

SELECT
    record_type,
    COUNT(*)
FROM t_f_budget_fact
GROUP BY record_type;  -- 'plan' and 'fact' counts
```
